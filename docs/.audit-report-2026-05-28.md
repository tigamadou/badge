- Hierarchie des roles : tous les README et index transverses utilisent desormais "OPERATOR (1) < MODERATEUR (2) < ADMIN (3) < SUPER_ADMIN (4)" au lieu de l'ancienne grille a 3 niveaux.
- "Operateur" pouvait scanner ET gerer les inscriptions/badges dans l'ancienne doc utilisateur : remplace par "Operateur = scan uniquement", "Moderateur = inscriptions/badges/categories".
- "Equipes" vs "Categories" : la dualite est documentee dans `docs/features/gestion-equipes.md`, qui redirige vers `gestion-categories.md` pour le detail (memes entites en BDD).
- Termes "validation"/"approbation" : "approbation" et "approuver" sont conserves pour l'action metier (cf. boutons UI "Approuver"). "Validation" est utilise au sens de "verification de donnees".

- AdminShell / Header / Sidebar : aucun guide dedie pour le layout d'administration (note de l'agent D).

## Bugs ou anomalies code detectes (hors scope doc mais a transmettre)

Compilation des points "A signaler en Phase 3" des 4 agents qui decrivent des bugs/anomalies du CODE :

- **Route `/admin/scan-history` manquante** (Agent C) : `ScanPageClient.tsx` ligne 266 reference cette URL inexistante. Soit creer la page, soit rediriger vers `/admin/activity-logs?type=scan`.
- **Page `/admin/teams` cassee** (Agents A & C) : elle attend un tableau (`await res.json()`) mais l'API renvoie un objet pagine `{ data, total, page, totalPages }`. La liste ne s'affiche jamais. La page est par ailleurs orpheline (hors sidebar).
- **DELETE `/api/teams/[id]` sans verif existence ni cascade** (Agent C) : aucune verification prealable, aucune logique pour empecher la suppression d'une categorie liee a des inscriptions. La contrainte FK Prisma leve un 500 non type.
- **`scanLog.id` retourne la chaine litterale `"activity-log"`** (Agent C) : la reponse de POST `/api/scan` expose un champ trompeur (suggestion : retourner l'`id` reel du log cree).
- **`/admin/categories` sans garde-fou de role cote UI** (Agent C) : seul le middleware d'auth filtre. Un utilisateur OPERATOR authentifie pourrait naviguer manuellement vers la page (le serveur 403 sur les actions API uniquement).
- **`src/app/scan/scanTicketExample.jsx`** (Agent C) : fichier d'exemple a supprimer ou a deplacer hors `src/app/`.
- **`smtpPassword` retourne en clair dans GET `/api/settings`** (Agent D) : seul `recaptchaSecretKey` est exclu de la reponse. Sujet de securite (lecture publique).
- **`/api/upload` valide MIME/taille AVANT de verifier l'auth** (Agent B) : pour `type=logo`, la validation de fichier s'execute avant de verifier que l'appelant est ADMIN.
- **`REGISTRATION_RESUBMITTED` et `EDIT_LINK_SENT` absents de `TYPE_GROUPS`** (Agents B & D) : enregistres en BDD mais masques par le filtre "Inscriptions" de l'UI du journal.
- **Desynchronisation pagination 20 (UI) vs 30 (API) journal** (Agent D) : `pageSize=20` cote UI mais `limit=30` par defaut cote API.
- **Rendu PDF depend de Google Fonts (Montserrat)** (Agent B) : dependance reseau externe (`fonts.googleapis.com`) non geree en offline. Maintenant documentee dans installation.md mais le code lui-meme pourrait beneficier d'un fallback local.
